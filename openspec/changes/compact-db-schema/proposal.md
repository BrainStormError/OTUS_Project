# Compact DB Schema

## Why

Схема БД накопила дублирование и неэффективные типы: `uuid`-ключи (16 байт), текстовые enum-поля, текстовые массивы жанров/тегов, копии метаданных медиа (`title`/`year`/`genres`) в каждой оценке, denormalized `jsonb`-payload в ленте и рассинхрон событий с реальными оценками. Данные seed не отражают реальных связей (события ссылаются на несуществующие оценки, у групп нет участников, лимит комментария не проверяется). Нужна компактная нормализованная модель со связями строго по числовым id.

## What Changes

- **BREAKING**: все первичные и внешние ключи становятся `bigint GENERATED BY DEFAULT AS IDENTITY`; связи — только по числовым id, `uuid`/`gen_random_uuid`/`pgcrypto` удаляются.
- **BREAKING**: вводится сущность `media` (kind, external_ref, title, year, genre_ids) — единый источник метаданных вместо копий в `watched_records`, `group_ratings` и пары `media_kind`/`media_ref` в `group_discussions`.
- **BREAKING**: `watched_records` и `group_ratings` объединяются в `ratings` с nullable `group_id` (NULL — личная оценка, задан — оценка в группе).
- Жанры и теги: справочники `genres`/`tags` (`smallint` id) + массивы id (`media.genre_ids`, `groups.tag_ids`) вместо `text[]`.
- **BREAKING**: `activity_events` теряет `payload jsonb` и полиморфный `target_type`/`target_id`; вводятся nullable FK `media_id` и `discussion_id`. Лента восстанавливает title/rating/href джойнами.
- Все пользовательские тексты ограничиваются 1000 знаками (CHECK в БД + max в zod).
- Enum-поля (`role`, `status` дружбы, `media.kind`, `activity.kind`, роль участника) — `smallint`-коды вместо `text`.
- Оценка хранится как `smallint` (0..100, десятые доли) вместо `numeric(3,1)`.
- Существующие миграции 0..11 переписываются под новую схему.
- Новый модуль `ratings` владеет объединённой таблицей; `records` и `groups` используют его public-поверхность.
- Переписываются репозитории, сервисы, route handlers, UI-фича `movie-tracker`, кодирование курсора ленты, `next-auth` (id пользователя — число) и тестовые данные (`scripts/seed-dev.ts`).

## Capabilities

### New Capabilities

- `data-model`: требования к схеме хранения — числовые идентификаторы и связи по id, компактные типы, нормализованное медиа, объединённые оценки, справочники жанров/тегов, целостность ленты через FK, ограничение пользовательского текста 1000 знаками и осмысленные согласованные тестовые данные.

### Modified Capabilities

Нет. Поведение UI-спецификаций (`ui/*`) не меняется: состав экранов, навигация и состояния интерфейса сохраняются.

## Impact

- **Миграции**: `src/core/db/migrations/` — 12 файлов переписываются в компактный набор (users, media+genres, ratings, friendships, groups+members+tags, group_discussions, discussion_posts, activity_events).
- **Модули**: новый `src/modules/ratings`; правки `auth`, `records`, `groups`, `discussions`, `friendships`, `activity` (типы, zod, repository, service).
- **API**: route handlers с `[id]`/`[media]` переходят на числовой парсинг; DTO возвращают числовые id; формат ответов ленты (`toFeedEvent`) строится без `payload`.
- **Auth/session**: `src/types/next-auth.d.ts`, `src/modules/auth/auth.ts` — `uid`/`user.id` как число.
- **UI**: `src/components/features/movie-tracker/*` (адаптеры, лента, формы), fallback-handle для числовых id.
- **Типы/pg**: единый парсер `int8` в node-postgres (bigint приходит строкой).
- **Данные**: `scripts/seed-dev.ts` переписываются; тесты — integration (activity, feed, db, migrations, discussions, group-ratings, group-feed), unit (схемы, сервисы, feed), e2e (group-discussions и др.).
