## Context

См. `proposal.md` — Why. Текущее состояние:

- `src/app/(app)/groups/[id]/page.tsx` — `force-dynamic` серверный компонент: выбирает активную вкладку из `searchParams.tab`, тянет данные только активной вкладки и рендерит её панель. Шапка и `GroupTabs` рендерятся в том же компоненте.
- `GroupTabs.tsx` — ссылки `<Link href="?tab=...">`; переключение = серверная навигация с полной перерисовкой сегмента.
- `Suspense`/`loading.tsx` в проекте не используются.
- Есть примитивы скелетов: `src/components/ui/skeleton.tsx` (`Skeleton`, `SkeletonText`, `SkeletonCard`, `SkeletonGrid`) и `AsyncView` с состоянием loading.
- Данные табов: `listDiscussions`/`getDiscussion`, `listGroupRatings`, `listGroupFeed`; «Участники» — из самого `group`; «Статистика» — placeholder (`EMPTY_STATS`).

## Goals / Non-Goals

**Goals:**

- При переключении вкладки шапка группы и панель вкладок остаются на месте.
- Пока грузится содержимое вкладки — виден skeleton по форме этой вкладки.
- Сохранить URL-адресацию (`?tab=`), deep-links и серверную проверку доступа.

**Non-Goals:**

- Клиентские API для вкладок и кэширование данных между переключениями.
- Наполнение вкладки «Статистика» реальными данными.
- Мгновенный контент без серверного запроса (это отдельный, более крупный апгрейд).

## Decisions

### 1. Suspense вокруг панели, ключ по вкладке

Панель оборачивается в `<Suspense key={active} fallback={<GroupTabSkeleton tab={active} />}>`. `key={active}` гарантирует свежую границу на каждое переключение, поэтому fallback показывается сразу, а не «залипает» предыдущий контент. Шапка и `GroupTabs` остаются вне границы и не мигают.

### 2. Данные вкладки — в async-компоненте

Забор данных из `page.tsx` переносится в отдельные асинхронные серверные компоненты (`DiscussionsPanel`, `RatingsPanel`, `ActivityPanel`; «Участники» и «Статистика» остаются лёгкими). Компонент сам вызывает сервисы, поэтому он «подвешивается» и стримится; страница-оболочка рендерится быстро.

- Почему: Suspense срабатывает только если дочерний компонент действительно suspends — fetch обязан быть внутри него, а не до рендера.
- Сохранение доступа: каждый сервис по-прежнему выполняет собственную проверку (`canViewGroup`), как требует `security/group-access`; новых открытых путей нет.

### 3. Skeleton по форме вкладки

`GroupTabSkeleton` выбирает форму: список строк (обсуждения/оценки/активность/участники) или карточки статистики, на базе `Skeleton`/`SkeletonList`. Формы совпадают с ожидаемым содержимым, как требует `ui/interface-states`.

### 4. Файлы

- `src/components/features/movie-tracker/GroupTabPanels.tsx` — async-панели (серверные).
- `src/components/features/movie-tracker/GroupTabSkeleton.tsx` — fallback-скелеты.
- `src/app/(app)/groups/[id]/page.tsx` — оставить выбор активной вкладки, обернуть панель в Suspense.

## Risks / Trade-offs

- [Заголовок всё ещё ждёт `getGroup` до рендера оболочки] → запрос группы лёгкий; шапку в отдельный Suspense не выносим осознанно.
- [`key={active}` пересоздаёт границу] → при возврате на уже открытую вкладку данные тянутся снова; кэш между вкладками вне объёма.
- [Streaming и `force-dynamic`] → страница уже динамическая, стриминг совместим; SSR-поведение сохраняется.
- [Вкладка «Статистика» показывает пустой скелет/пустое состояние] → существующее отсутствие данных, не регресс.
