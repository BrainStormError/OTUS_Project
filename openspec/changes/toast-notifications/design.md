## Context

См. `proposal.md` — Why. Текущее состояние фидбека:

- `Banners` (`src/components/layout/banners.tsx`) — серверные info/warning-полосы, не тосты; остаются как есть.
- Ошибки форм показываются inline (`role="alert"`), например в `GroupDiscussions.tsx`; `PrivacyToggle.tsx` держит собственный `SaveStatus` (`saving`/`saved`/`error`).
- Часть мутаций после успеха делает `router.refresh()` (`GroupDiscussions.tsx`), часть — оптимистичный локальный стейт и fire-and-forget fetch (`social-actions.ts`), где `.catch(() => undefined)` глушит ошибку.
- Единой точки показа исхода нет; Radix-зависимостей, кроме `@radix-ui/react-slot`, нет.
- Дизайн-система ограничивает движение (fade/slide 150–250 мс, reduced-motion) и требует live-region для асинхронных изменений и тач-таргетов 44px.
- Оболочка приложения — `src/app/(app)/layout.tsx` (серверный компонент) с `SidebarRail`, `TopBar`, `main`, `Footer`, `MobileTabBar`.

## Goals / Non-Goals

**Goals:**

- Один механизм тостов, пригодный для вызова из любого клиентского компонента.
- Сообщать и успех, и ошибку мутирующих действий.
- Соответствие `ui/notifications`, `ui/design-system` и `ui/accessibility`.

**Non-Goals:**

- Центр уведомлений, история тостов, «непрочитанные».
- Real-time уведомления на основе `activity_events` / SSE — только подтверждение собственных действий пользователя.
- Замена inline-ошибок форм и `Banners`.
- Серверный (SSR) рендер содержимого тостов.

## Decisions

### 1. Основа — `@radix-ui/react-toast`

Берём Radix Toast вместо самописного тостера: даёт вьюпорт, стекирование, паузу при наведении/фокусе, авто-скрытие, свайп и live-region (`role="status"` / `aria-live`) без ручной реализации хрупких деталей.

- Почему: закрывает доступность и поведение из `ui/notifications` без собственного кода; стилизуется существующими токенами.
- Альтернатива: свой контекст + таймеры — больше кода и риска по a11y; отклонено.

### 2. Провайдер и вьюпорт

Новый клиентский `src/components/ui/toast.tsx`: `ToastProvider` (оборачивает `ToastProvider` Radix) + `ToastViewport`. Монтируется в `src/app/(app)/layout.tsx` вокруг `children`. Императивный доступ — хук `useToast()`, возвращающий `{ success(message), error(message) }`; хук — тонкая обёртка над контекстом Radix.

- Почему: провайдер один на приложение, вызов из любого клиентского компонента; SSR-содержимое тостов не требуется.

### 3. Где вызывается тост

Тост поднимается в месте обработки результата, а не внутри «глухого» помощника:

- Компоненты с `async`-обработчиком (`RecordModal`/`report-rating.ts`, `GroupDiscussions`, `SettingsView`/`PrivacyToggle`, `CreateGroupModal`, админ-панель) вызывают `toast.success`/`toast.error` по итогу `fetch`.
- `social-actions.ts` сейчас fire-and-forget и глушит ошибки. Его помощники станут возвращать `Promise`, а вызывающий (`FriendsView`) покажет тост; при ошибке локальный оптимистичный апдейт откатывается и показывается error-тост.
- Для успешно отправленного отказа от подписки и т.п. сообщения формулируются коротко на русском («Запись сохранена», «Не удалось сохранить запись»).

### 4. Тон и токены

Успех и ошибка различаются **иконкой и текстом**, не только цветом (требование `ui/notifications`). Ошибка использует существующий `destructive`-токен (как inline-ошибки). Успех — нейтральная карточная поверхность (`bg-card`, `border-border`) с иконкой-галочкой, без новых «ядовитых» цветов: дизайн-система запрещает зелёный акцент и градиенты.

- Почему: соответствие «Strictly matte palette» и «Accent reserved for brand marks».

### 5. Тайминги

Авто-скрытие: успех ~4 с, ошибка ~6 с (ошибку читают дольше). Наведение/фокус ставят таймер на паузу (поведение Radix). Число одновременных тостов ограничивается вьюпортом; дедупликации на первом этапе нет.

## Risks / Trade-offs

- [Помощники `social-actions.ts` сейчас глушат ошибки] → перевести на возврат `Promise` и показывать тост в вызывающем коде; это меняет их сигнатуры и затрагивает существующие unit-тесты — обновить вместе с реализацией.
- [Оптимистичные апдейты без отката] → при ошибке откатывать локальный стейт, иначе UI разойдётся с сервером при показе error-тоста.
- [Много мест привязки] → перечень в `tasks.md`; пропущенное место не ломает сборку, но не даёт фидбека — ревью по чек-листу мутаций.
- [Новая зависимость] → единственный новый пакет; Radix уже принят в проекте (`react-slot`), CSP по скриптам не затрагивается (бандл, не inline).
- [Дублирование с inline-статусом приватности] → `PrivacyToggle` сохраняет свой `SaveStatus`; тост дополняет его, не удаляем существующее.

## Migration Plan

- Добавить `@radix-ui/react-toast`; `npm install`.
- Ввести провайдер/вьюпорт и хук, смонтировать в оболочке.
- Привязать места мутаций из `tasks.md`.
- Откат: убрать провайдер и вызовы `useToast`; изменения помощников `social-actions.ts` откатываются вместе с фичей.
