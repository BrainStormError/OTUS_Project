## Why

Замеры на стенде показали, что время уходит не в сеть и не в бандл: TTFB документа ~726 мс при 16 мс на загрузку тела, соединение тёплое, HTTP/2 включён. Сервер тратит время на рендер React и запросы в базу на каждом клике. При этом приложение авторизованное и личное — SEO-ценности SSR не даёт вообще, а `export const dynamic = 'force-dynamic'` в корневом layout (вызван per-request CSP-нонсом) запрещает любое кэширование: из `prerender-manifest.json` пререндерены только `/icon.svg` и `/_global-error`.

Итог: каждый визит стоит полный рендер на сервере, и ничего из этого нельзя закэшировать ни в браузере, ни в CDN.

## What Changes

- **BREAKING:** HTML приложения перестаёт содержать данные пользователя и перестаёт требовать сессию. Оболочка отдаётся как статический ресурс, данные приходят через `/api/*`.
- **Снимается `force-dynamic`** из `src/app/layout.tsx`. Страницы собираются на сборке и кэшируются.
- **CSP переводится с per-request нонса на hash-based** (`'sha256-...'`). HTML становится байт-в-байт одинаковым, нонс больше не нужен.
- **`proxy.ts` перестаёт генерировать нонс на каждый запрос** и больше не является обязательной точкой на пути статики.
- **Авторизация уезжает на уровень данных.** Серверный `redirect('/login')` в layout заменяется клиентским guard'ом плюс проверкой наличия куки в `proxy.ts`; настоящая проверка сессии остаётся на сервере в каждом `/api/*`.
- **Страницы переводятся на клиентские данные по одной за раз.** Оболочка (меню, шапка, подвал) остаётся на месте на каждом шаге.
- **Появляются недостающие эндпоинты чтения:** статистика пользователя и просмотр профиля по handle — сейчас эти данные есть только в серверных модулях.
- **BREAKING:** скелетоны загрузки убираются. `loading.tsx`, `RouteLoadingSkeleton` и связанные с ними компоненты удаляются; отдельное состояние загрузки не рисуется. Это осознанно отменяет требование `ui/interface-states` о скелетонах.

## Capabilities

### New Capabilities

- `security/content-security`: как браузеру разрешается исполнять скрипты приложения — hash-based политика для статического HTML вместо одноразового нонса на каждый запрос.

### Modified Capabilities

- `platform/authorization`: оболочка приложения становится публичной; решения о доступе к данным остаются на сервере и принимаются для каждого запроса данных.
- `platform/http-contract`: контракт распространяется на чтение — эндпоинты чтения так же требуют сессию, проходят валидацию и отдают типизированные ошибки. Раньше контракт покрывал только мутации.
- `ui/interface-states`: требования о скелетонах загрузки отменяются — состояние загрузки отдельно не отображается.

## Impact

- **Code:** `src/app/layout.tsx` (снятие `force-dynamic`), `src/app/(app)/layout.tsx` (перенос guard'а и identity на клиент), `src/proxy.ts` (hash-based CSP вместо нонса), страницы `src/app/(app)/**/page.tsx` (клиентские данные, по одной за раз), `src/app/api/me/stats/route.ts` и `src/app/api/profiles/[handle]/route.ts` (новые), удаление `src/app/**/loading.tsx`, `src/components/features/RouteLoadingSkeleton.tsx` и, если больше нигде не используется, `src/components/ui/skeleton.tsx`.
- **Tests:** e2e (15 файлов) — проверить, что сценарии переживают переход на клиентские данные; unit — guard авторизации, hash-based CSP, новые эндпоинты чтения.
- **Безопасность:** разметка становится видимой без логина, данных в ней нет. Защита данных не меняется: `withRoute` по-прежнему требует актора, роль читается из БД. Решения о правах в клиент не переносятся.
- **Координируется с:** change `runtime-cost-trims-followup` (снять нагрузку с ядра до того, как мерить эффект от статики) и change `runtime-cost-trims` (заархивировать первым).
