## Why

Переключение вкладок внутри группы — самая дорогая операция приложения: каждый клик по вкладке — это полный `force-dynamic` SSR страницы `/groups/[id]`, который за один рендер3–4 раза заново загружает одну и ту же группу со всеми участниками (`canViewGroup` вызывается в `GroupPage`, внутри `getGroup` и снова внутри панелей — ~12 SQL на клик, из них 8 дубли). На VPS (1 vCPU, 1 ГБ RAM) это даёт постоянную CPU-нагрузку при работе (app ~30% + db ~9% при активных переходах) и ощутимо медленные переходы именно внутри группы.

## What Changes

- **Вкладки группы становятся клиентским состоянием (вариант C1).** При открытии страницы группы данные всех панелей (обсуждения, оценки, активность, участники, статистика) готовятся за один серверный проход; переключение вкладки показывает уже готовую панель мгновенно, без запроса на сервер и без скелетона загрузки. Это выравнивает группу с уже существующим паттерном вкладок «Мои фильмы»/«Мои сериалы» (`MyFilmsView`: `useState` + данные с сервера пропсами).
- **URL остаётся адресуемым.** Активная вкладка (`?tab=`) и открытая дискуссия (`?discussion=`) синхронизируются с адресной строкой через history API без серверной навигации: перезагрузка страницы и диплинки из ленты активности (`/groups/N?tab=discussions&discussion=M`) открывают ту же вкладку и ту же дискуссию. Переключение вкладок перестаёт добавлять записи в историю браузера: кнопка «Назад» с группы возвращает на предыдущий экран, а не проходит по вкладкам.
- **Дедупликация запросов группы.** Загрузка группы (`findGroupById`: группа + теги + участники) и проверка роли (`getGroupRole`) выполняются один раз на серверный запрос вместо3–4 повторов (`react.cache` на уровне запроса), включая повторный `canViewGroup` внутри сервисов панелей. Оставшиеся переходы (диплинк на дискуссию, обновление после мутации) дешевеют пропорционально.
- **Не меняется:** главная навигация между разделами остаётся серверной (prefetch + Router Cache), панели остаются серверными компонентами с данными в пропсах, HTTP-контракт и права доступа не меняются.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `ui/screens`: поведение вкладок страницы группы — переключение вкладок на месте без серверного круга, с сохранением адресуемости вкладки и дискуссии в URL.

Оптимизация повторных запросов группы — деталь реализации, наблюдаемого поведения не меняет, отдельного требования не создаёт.

## Impact

- **Code:** `src/app/(app)/groups/[id]/page.tsx` (один проход данных всех панелей), `src/components/features/movie-tracker/GroupTabs.tsx` (клиентский контроллер вкладок вместо `Link`-навигации), `GroupTabPanels.tsx`, `src/modules/groups/service.ts` (дедупликация `findGroupById`/`getGroupRole`/`canViewGroup` через `react.cache`).
- **Tests:** unit-тесты контроллера вкладок (мгновенное переключение без навигации, отражение вкладки в URL, открытие диплинка `?discussion=`, поведение кнопки «Назад»), тесты дедупликации запросов группы; существующие тесты вкладок группы и e2e (`group-*.spec.ts`) должны продолжать проходить.
- **Data/API:** без миграций, без изменений HTTP-контракта; `router.refresh()` после мутаций в панелях сохраняется, но дешевеет за счёт дедупликации.
- **Не затрагивается:** навигация разделов, TMDB-кэш, бюджеты ресурсов (`vps-resource-budgets`), схема БД.
