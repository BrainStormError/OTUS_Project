# Real User Search

## Why

Поиск людей на странице «Друзья» работает по мок-данным (`data.ts`), а не по БД, кнопка «Добавить» никуда не ведет (API отправки заявок отсутствует), и собственный профиль может оказаться в выдаче. Поиск людей должен работать через БД, а отправка заявок — быть настоящей.

## What Changes

- Новый поиск людей по БД: сначала совпадения среди друзей пользователя, при отсутствии — все непрошедшие `profile_hidden` профили; собственный профиль никогда не попадает в выдачу.
- Кнопка «Добавить» в результатах поиска отправляет настоящую заявку в друзья: новый route handler + сервисный сценарий + политика (нельзя добавить себя, повторно, или уже дружащих).
- Раздел «Заявки» показывает исходящие заявки (сейчас — только входящие), с возможностью отозвать отправленную заявку.
- Поиск по группам не затрагивается (уже работает на данных из БД).

## Capabilities

### New Capabilities

- `social/user-search`: доменное поведение поиска людей и отправки заявок — область видимости результатов (свои друзья → все неоткрытые профили), исключение самого себя, статусы отношений в выдаче (друг / заявка ожидает / нет), правила создания заявки.

### Modified Capabilities

- `ui/screens`: требование «Friends screen» — выдача поиска людей из БД с рабочим действием отправки заявки; исходящие заявки отображаются в разделе «Заявки». Требование «Scoped search in Friends and Groups» — собственный профиль исключен из выдачи поиска людей.

## Impact

- `src/modules/friendships` — новые сценарии: поиск пользователей, создание заявки, отзыв заявки; миграция не требуется (схема `friendships` уже подходит).
- `src/app/api/friendships` — новые route handlers (`POST /api/friendships`, `DELETE /api/friendships/[id]`, `GET /api/friendships/search`).
- `src/components/features/movie-tracker/FriendsView.tsx`, `data.ts` — поиск уходит от моков к API; мок-фолбэк `searchFriends`/`otherUsers` удаляется из боевого пути.
- Политика `core/auth/policy.ts` — новые действия.
- Тесты: unit (политика, схемы), integration (поиск, создание/отзыв заявки), e2e-путь «найти → добавить → принять».
