## Why

Нагрузка на VPS пропорциональна трафику, и у каждого действия есть «умножители»: открытие любой страницы молча рендерит все 6–7 пунктов меню (автопрефетч), каждый запрос заново читает пользователя из базы, каждый поиск заново читает словарь жанров, а sweep кэша TMDB каждые ≤5 минут детоастит до 100 МБ JSON ради подсчёта размера. Плюс `revalidatePath` ×9 на каждую мутацию личных списков — по спайку из `records-store-and-revalidate` они не сбрасывают клиентский Router Cache и свежесть несут впустую. Память уже в бюджете (`vps-resource-budgets` задеплоен: RSS ~85 МБ, swap плоский) — осталось снять стоимость запросов.

## What Changes

- **Prefetch по намерению и в простое (п.1).** Пункты меню перестают префетчиться автоматически все сразу при появлении страницы; вместо этого `router.prefetch()` вызывается по наведению/фокусу/тапу на пункт и последовательно прогревает пункты меню в простое браузера. Карточки каталога по-прежнему не префетчатся.
- **Кэш актора (п.2).** Результат `resolveActor` (пользователь из БД) кэшируется в памяти процесса с TTL ≤60 с и инвалидируется мутациями профиля. Роль по-прежнему берётся только из БД (через кэш, никогда — из токена); сброс кэша при смене имени/ника даёт мгновенную видимость изменений.
- **Кэш словаря жанров (п.3).** Список жанров из БД кэшируется в памяти процесса (TTL ~10 мин) вместо SQL-чтения на каждый поиск; деплой перезапускает процесс, поэтому синхронизация жанров видна сразу после деплоя.
- **`Cache-Control` на `/api/genres` (п.4).** Ответ отдаётся с `private, max-age ≤ 3600` — браузер перестаёт опрашивать эндпоинт при каждом открытии модалки.
- **Дешёвый учёт размера кэша TMDB (п.5).** В `tmdb_cache` добавляется колонка `payload_bytes` (миграция с одноразовым backfill), записывается при upsert; `selectCacheUsageBytes` и вытеснение считаются по целочисленной колонке вместо детоаста всех payload'ов — sweep перестаёт читать до 100 МБ JSON каждые ≤5 минут.
- **`jit=off` для Postgres (п.7).** Флаг добавляется в `command:` сервиса `db` рядом с текущей настройкой; JIT-компиляция планов на мелких запросах тратит CPU, не окупаясь.
- **Убрать `revalidatePersonalData` (п.8).** Вызовы `revalidatePath` ×9 удаляются из мутаций `/api/records` и `/api/watchlist`: свежесть между разделами несёт общий стор (спайк в `records-store-and-revalidate`), а e2e `records-freshness` остаётся стражем поведения.
- **Не меняется:** п.6 (интервал healthcheck) в этот change не входит; HTTP-контракт (кроме одного заголовка), права доступа, схема поведения экранов остаются прежними.

### Modified Capabilities

- `platform/authorization`: требование «Actor role comes from the source of truth» — чтение актора допускает короткоживущий серверный кэш (старение ≤60 с), явная инвалидация при мутациях профиля; роль по-прежнему только из БД.
- `ui/navigation`: требование «Shell links prefetch their destination» — префетч становится намеренным (hover/focus/touch) и фоновым в простое, а не автоматическим на все ссылки при появлении; клик без префетча работает обычной навигацией. Требование введено change'ом `navigation-performance` — его нужно заархивировать до архивации этого change.
- `catalog/genres`: добавляется требование кэшируемости ответов словаря жанров с ограниченной свежестью (клиентский кэш ≤1 часа; серверный кэш короче) — синхронизация жанров видна клиентам в пределах этого срока.

П.5, п.7, п.8 — детали реализации, наблюдаемое поведение не меняют, отдельных требований не создают.

## Impact

- **Code:** `src/components/layout/nav-links.tsx` (prefetch по намерению + прогрев в простое), `src/modules/auth/actor.ts` (+ мутации `/api/me/identity` — инвалидация кэша), `src/modules/catalog/service.ts` (кэш жанров), `src/app/api/genres/route.ts` (заголовок Cache-Control), `src/modules/catalog/cache-repository.ts` (учёт по `payload_bytes`), `src/app/api/personal-revalidate.ts` (удаление) и вызовы в `src/app/api/records/route.ts`, `src/app/api/watchlist/route.ts`.
- **Infra:** `docker-compose.yml` — `-c jit=off` в `command:` сервиса `db`.
- **DB:** одна новая миграция (`tmdb_cache.payload_bytes` + backfill `octet_length(payload::text)`); обратная миграция удаляет колонку. Откат кода требует down-миграции: колонка `NOT NULL` без DEFAULT, старый код её не заполняет — без удаления колонки запись кэша на новых ключах падает с нарушением NOT NULL. Альтернатива (генерируемая колонка `GENERATED ALWAYS AS octet_length(payload::text) STORED`) сделала бы откат безопасным без down-миграции, но отклонена в пользу меньшей схемы.
- **Tests:** unit — кэш актора (TTL, инвалидация, роль из БД), кэш жанров, Cache-Control, учёт `payload_bytes` (usage и порядок вытеснения не изменились), отсутствие `revalidatePath` в роутах; e2e `records-freshness` проходит без изменений.
- **Координация:** change опирается на реализацию sweep'а из `vps-resource-budgets` (задеплоена) и на требование префетча из `navigation-performance` (архивировать первым).
