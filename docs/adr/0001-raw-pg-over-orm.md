# ADR 0001. PostgreSQL через `pg`, без ORM

## Статус

Принято.

## Контекст

Проект рассчитан на малый хостинг (один контейнер приложения + одна БД) и небольшую
команду. Нужны предсказуемая память, прозрачный SQL и прямой контроль над индексами
и транзакциями.

## Решение

Использовать `pg` с рукописным параметризованным SQL за репозиторием каждого модуля
(`modules/*/repository.ts`). Один общий `pg.Pool` на процесс (`core/db/pool.ts`),
транзакции открывает сервис (`core/db/transaction.ts`), репозиторий принимает `PoolClient`.

## Альтернативы

- **Prisma / Drizzle** — кодогенерация и более тяжёлый рантайм; избыточно для scope.
- **Query builder** — добавляет абстракцию, не убирая SQL.

## Последствия

- Плюсы: прозрачность, малый набор зависимостей, контроль индексов и транзакций.
- Минусы: риск расхождения запросов и типов → митигируется локальным маппингом
  `snake_case → camelCase`, именованными колонками в `RETURNING` и integration-тестами.
- Изменение схемы — только миграцией (`node-pg-migrate`); правка `schema.sql` как источника
  истины запрещена.
