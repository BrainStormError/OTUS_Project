# ADR 0003. Правила зависимостей слоёв проверяются автоматически

## Статус

Принято.

## Контекст

Слоистая архитектура (`app -> modules -> core`) и изоляция модулей — правила,
которые легко нарушить незаметно, если они живут только в документе.

## Решение

Правила закодированы в `.dependency-cruiser.cjs` и выполняются в блокирующем CI-шаге
`npm run deps:check`:

- `core-not-to-modules-or-components` — `core` не знает о `modules`/`components`.
- `ui-not-to-modules` — `components/ui` не зависит от домена.
- `no-cross-module-repository` — модуль может обращаться к другому только через
  публичный surface (`index.ts`), но не к его `repository`.
- `no-circular` — без циклических зависимостей.

Чтобы `core/http/with-route.ts` не импортировал `modules`, резолвер актора
инжектируется из app-слоя (`resolveActor: getActor`) — инверсия зависимости.

## Альтернативы

- **ESLint import rules** — слабее моделируют пути/алиасы.
- **Только code review** — не автоматизировано.

## Последствия

- Нарушение слоя валит сборку (проверено probe-файлами в обе стороны).
- Правила поддерживаются в одном конфиге.
