# ADR 0005. Гейт аудита ограничен production-зависимостями

## Статус

Принято.

## Контекст

После апгрейда рантайма (ADR 0004) `npm audit` всё ещё находит advisories, но все они
находятся в **dev-toolchain** и не попадают в production-образ:

- `braces` (high) тянется через `eslint-config-next` → `@next/eslint-plugin-next` →
  `fast-glob` → `micromatch`. Установлена последняя версия `braces@3.0.3`, но advisory
  помечает все версии, и апстрим-фикса нет — версией это не лечится.
- Прочие — транзитивные dev-зависимости тестовой сборки.

Блокирующий гейт должен отражать риск, попадающий в прод, и при этом быть зелёным,
иначе он теряет смысл.

## Решение

`npm run audit` выполняет `npm audit --omit=dev --audit-level=high` — проверяется только
production-дерево. Оно даёт **0 уязвимостей**. Dev-advisories отслеживаются отдельно
(обновление инструментов, отслеживание апстрим-фиксов).

## Альтернативы

- **Оставить `npm audit --audit-level=high`** — вечно красный из-за нефиксируемого
  dev-advisory; такой гейт игнорируют.
- **Allowlist-файл** — скрывает проблему хуже, чем явное разделение scope.

## Последствия

- Прод-риск покрыт блокирующим гейтом.
- Изменение scope задокументировано здесь и в `GUIDE.md`; при появлении фикса `braces`
  правило можно вернуть к полному аудиту.
