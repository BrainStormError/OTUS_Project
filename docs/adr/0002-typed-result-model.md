# ADR 0002. Типизированный `Result` для ожидаемых отказов

## Статус

Принято.

## Контекст

Ожидаемые отказы (валидация, авторизация, бизнес-правила) не должны становиться
control flow через `try/catch`, а непредвиденные сбои (БД недоступна) не должны
маскироваться под бизнес-ответ.

## Решение

`core/result.ts` задаёт `Result<T> = Ok<T> | Err` с `ok()` / `err(code, message)`.
Сервисы возвращают `Result`; `core/http/with-route.ts` маппит код в HTTP-статус
(`VALIDATION→400`, `UNAUTHORIZED→401`, `FORBIDDEN→403`, `NOT_FOUND→404`,
`CONFLICT→409`, `RATE_LIMITED→429`, `INTERNAL→500`). Непредвиденные исключения
ловятся обёрткой → 500 с записью в лог и без деталей наружу.

## Альтернативы

- **Исключения для всего** — ожидаемые пути становятся `catch`-контролем.
- **`null`/boolean** — теряется код причины.

## Последствия

- Ожидаемые исходы исчерпывающе обрабатываются и тестируются (RS-тесты на каждый статус).
- 500 зарезервирован под реальные дефекты.
- Клиентские компоненты отображают `Result`, не решая права.
